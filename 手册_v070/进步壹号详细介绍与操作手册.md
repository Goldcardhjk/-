## 一、这是一款什么软件

进步壹号 Agent 是一款**本地优先的人际关系经营工作台**。它要解决的不是「把联系人存起来」，而是三件更难的事：

> **微信里躺着三千个好友，真到要开口那天，一个都不敢点。**
> 不是不想维护，是记不住谁帮过谁、谁欠着谁。

软件围绕三个核心能力构建，本手册也按这三条主线组织：

| # | 核心功能 | 解决的问题 | 主要入口 |
|---|---|---|---|
| **一** | **关系网络的直观性** | 一眼看清每个人和你的关系、人和人之间的关系 | 「关系网络」页 |
| **二** | **Agent 自主推断关系属性** | 把你没录入、甚至没意识到的关系补出来并给出依据 | 「大模型判断关系」按钮 |
| **三** | **关系改善与升温** | 告诉你今天该联系谁、怎么联系、联系完记一笔 | 右侧任务栏 + 祝福语 / 智能送礼页 |

**产品定位的三条边界**（理解这三条，才能正确使用本软件）：

1. **本地优先**：所有人物、关系、互动记录默认存在本机 SQLite 数据库，不上传。界面原话：「本地账号 · 数据仅存本机（D 盘 SQLite），不上传。」
2. **不凭空编造关系**：Agent 推断受多层硬约束（详见核心功能二第 4 节）。亲属关系一律由规则推导，模型无权生成。
3. **真实 AI 调用才计费**：本地模板、本地检索、本地评分全部免费；只有真正打到大模型 API 的操作按积分扣费。

软件主界面分为五个页签：

| 页签 | 作用 |
|---|---|
| **关系网络** | 主页。关系图谱 + 右侧任务栏（提醒 / 概览 / 快速补关系 / 优先级 / AI 助手） |
| **人脉卡片** | 以卡片列表形式批量查看与编辑人物资料 |
| **智能送礼** | 按喜好与禁忌推荐礼物、多商家比价、下单 |
| **祝福语** | 单人定制祝福、节日群发、分档模型配置 |
| **绿泡泡连接器** | 从联系人沙盒拉取好友、触发大模型关系判断 |

## 二、五分钟上手

### 2.1 启动与选账号

双击 `JinbuYihaoAgent_v069.exe`。启动时会先出现原生加载页，并显示真实初始化阶段：

> 正在准备本地数据… → 正在读取账号与场景… → 正在打开账号入口…

加载完成后进入**账号入口层**（不是弹窗，就在主窗内）：

![账号入口层](shots/00_account_gate.png)

界面要点：

- 标题「**选择账号进入**」，说明文字「每个人物、每一段记忆，都跟着账号走——工作号归工作号，生活号归生活号。」
- 每张账号卡显示该账号的规模，例如「工作账号 — 18 位人物 · 3 个场景」。
- 「**＋ 新建账号**」卡用于「另开一份独立的人物与记忆」。
- 卡片底部注明隔离原则：「账号之间互不可见：一个账号一个 SQLite 库，切换不丢数据。」

点一下账号卡即**原地**进入主界面，不换窗口、不跳转。

### 2.2 第一次该做什么

推荐按这个顺序走，大约五分钟能跑完一轮完整闭环：

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | 「绿泡泡连接器」页 →「连接沙盒」→「一键拉取全部」 | 批量导入人物，并自动同步已知关系连线 |
| 2 | 回到「关系网络」页 | 看到整张关系图，顶部显示「共 N 位人物」 |
| 3 | 点「大模型判断关系」 | Agent 补出人物之间的关系、重算关系分 |
| 4 | 右侧任务栏看「维护优先级」与「近期提醒」 | 知道今天该联系谁 |
| 5 | 点提醒行上的「祝福」或「送礼」 | 直接进入升温动作 |
| 6 | 联系完，在资料卡点「记录联系」 | 记一笔，进入互动历史 |

> **没有联系人沙盒怎么办？** 也可以直接在「关系网络」页点「**加人**」，或在「人脉卡片」页新建卡片逐个录入。

### 2.3 启动性能说明

v0.69 做了启动性能优化：**关系首页优先构建，其余四页首次打开时才建**。因此首次点击「人脉卡片」「智能送礼」等页签会有短暂构建耗时，之后切换即时。

## 核心功能一：把人物关系画成一张看得懂的网

这是软件的主页，也是全部功能的地基。设计目标只有一个：**关系清晰、便于行动**——不为了几何上的整齐去牺牲可读性。

![关系网络全景](shots/10_network_all.png)

### 1.1 画面读法

打开「关系网络」页，你会看到：

- **中心是「我」**，显示当前账号的头像与名字。
- **四周是人物卡片**，自由二维分布，不要求排在同一个圆周上。
- 每张人物卡显示：头像、姓名、**分数与档位**（例如「86 分 · 核心」）。
- **每个人都与「我」有一条浅色细线相连**，这条线常驻，不依赖评分。

顶部工具条从左到右：

| 元素 | 说明 |
|---|---|
| 「关系网络」+ 「共 N 位人物」 | 当前场景下的人数 |
| 「场景」+ 场景卡 | 全部 / 办公 / 学校 / 家庭 / 管理 |
| 「加人」 | 新增人物 |
| 「连线」 | 进入连线模式，手动建立两人之间的关系 |
| 「更多」 | 备份恢复、积分充值、支付配置、云端账号等菜单 |
| 「面板」 | 显示 / 隐藏右侧任务栏 |

画布下方一行是图例：

> 卡片维护分：**核心 / 重要 / 普通 / 浅层**　·　浅细线＝与我相连　·　暖色线＝亲属关系　·　悬停展开其他关系　·　浅色区域＝圈子（勾选可全显）

### 1.2 两套颜色，各管一件事（重要）

这是本软件最容易被误解的一点，请务必分清：

| 颜色载体 | 含义 | 取值 |
|---|---|---|
| **卡片颜色** | **关系分档位**（维护优先级） | ≥80 核心（红 `#CE4258`）/ 65–79 重要（橙 `#B96A18`）/ 45–64 普通（蓝 `#2563EB`）/ <45 浅层（灰 `#63738A`） |
| **连线颜色** | **关系类型**（语义） | 家人红 / 挚友橙 / 合作伙伴青 / 同事绿 / 引荐紫 / 认识灰；**亲属线统一暖棕 `#AD7952`** |

> ⚠️ **不要说「线的颜色代表分数」。** 线色表达的是关系的**种类**，卡色表达的是关系的**深浅档位**。两套语义独立，人再多也不会认错。
>
> 关系分的数值会出现在卡片上的「86 分 · 核心」以及资料卡的连接行里（如 `[引荐·70分] 陈学长`），但**不以网络图线条的颜色呈现**。

### 1.3 场景卡：同一张网，换人群看

日常不需要靠切换账号来看不同人群。**场景是账号内部的视图过滤层**，一点即切。

![切到「办公」场景](shots/11_scene_office.png)

上图是点击「办公」后的状态：人数从 18 位收窄为 **6 位**，只剩同事与合作伙伴；提示文字变为「只看「办公」的人 · 点「全部」回到整张网」，状态栏显示「已切换到「办公」场景 · 共 6 人」。

![切到「家庭」场景](shots/12_scene_family.png)

切换场景时，**以下区域全部联动刷新**：

- 关系网络画布（人物与连线）
- 右侧「近期提醒」
- 右侧「网络概览」统计
- 右侧「维护优先级」排序
- 启动提醒弹窗

其他要点：

- 内置场景为 **办公 / 学校 / 家庭**，外加一个内置视图「**全部**」（「全部」不是数据表里的记录，而是不过滤的视图）。
- 一个人**可以同时属于多个场景**，在人脉卡片或资料卡里勾选。
- 场景可以自定义：点场景卡旁的「**管理**」可以新增、改名、删除、排序，改完不需要重启。
- **场景选择按账号持久化**，重启后自动回到上次用的场景。
- 若当前选中的场景被删除，自动回到「全部」，并提示「场景已变更 · 已回到「全部」」。

> 设计说明：v0.69 起**不再用底色色块划分人群区域**。划分与切换的职责完全交给场景卡，画布保持干净。

### 1.4 连线的显示策略：默认克净，按需展开

18 个人如果把所有关系线都画出来，整幅图就是一团线。所以采用三层策略：

**默认状态**：只显示**亲属线**（暖棕色），其余关系线隐藏（数据和标签都在，只是不占画布）。

**悬停某个人物**：只展开**与这个人相关**的关系线和标签。

![悬停聚焦](shots/14_hover_focus.png)

**勾选「显示全部连线」**：所有关系线与语义标签一次全显。

![显示全部连线](shots/13_all_links.png)

上图中可以读到各类语义标签：家人、同事、同事 · 引荐、认识、合作伙伴、合作伙伴 · 引荐、引荐、驴友等。勾选后状态栏提示「全部关系线和语义已显示」。

> **给自动化脚本的提示**：`_toggle_all_links` 是复选框的 command 回调。如果用代码直接调用它，必须先 `_show_all_links.set(True)`，否则等于没点。

### 1.5 画布交互全集

| 操作 | 效果 |
|---|---|
| **鼠标滚轮** | 缩放。连续滚动会合并重绘，不会卡顿 |
| **中键拖拽** | 平移视野。网络拖不出视口（滚动范围就是内容包围盒） |
| **左键拖拽人物卡** | 移动人物位置，松手即**固定并保存**坐标 |
| **鼠标悬停人物** | 高亮该人物，展开他的关系线与标签；光标变手型 |
| **左键点击人物** | 选中 |
| **右键点击人物** | 弹出菜单：打开资料卡 / 记录联系 / 连接到其他人物… / 去送礼 / 生成祝福 / 删除该人物 |
| **右键点击连线** | 弹出连接菜单（编辑或断开该条关系） |
| **右键点击空白** | 退出连线模式 |
| 「连线」按钮 | 进入连线模式，依次点两个人建立关系 |
| 「更多」→「背景」 | 开启 / 关闭画布背景纹理（点阵 + 中心柔光），默认关闭 |

### 1.6 布局：自由分布 + 手动固定 + 防重叠

- **自由二维布局**：人物按关系做力导向排布，位置可以很随意，但**每个人必须和「我」相连**。
- **防重叠**：矩形卡片相互压住时，沿重叠更小的轴各推一半，多轮迭代收敛，位移最小。
- **手动固定优先**：你**拖拽过**的卡片永不被自动推开——手一松位置就自己挪几像素，看着像「又自动布局了」，这个问题已修。
- **重置**：右键人物 →「重置位置」让单人回到自动布局；「更多」→ 自动布局（`reset_layout`）会清空**所有**手动位置，操作前有二次确认：「将清空所有手动固定位置并重新按人物关系自由排列，继续？」
- **自动适配**：人物集合发生变化（首次进入 / 拉取 / 增删）时，按包围盒自动缩放到能看全；你自己的拖动和手动缩放不会被重置。

### 1.7 中心线的特殊说明

「我 → 每个人」的连线是**展示层的联系，不是事实关系数据**。

- 18 个人就是 18 条线，如果画实了会盖住真正的亲属线，所以默认压到接近底色，只留方向感。
- 悬停某人时，把他那一根提亮，让「他和我」的关系读得清。
- **这些中心线不会被写进数据库**，软件不会为了让图好看而向库里补写虚构的人物间关系。

## 核心功能二：Agent 自主推断你没意识到的关系属性

录入人物时，你填的往往只是「他是谁、他的联系方式」。但社交圈里真正值钱的信息是**人和人之间的连接**，以及**你自己都没意识到的关系属性**——谁是枢纽、谁被谁引荐、哪两个人其实早就认识。

这一节的功能就是把这部分补出来。

### 2.1 入口与一次完整的推断

入口有两处：

1. 「**绿泡泡连接器**」页顶部的绿色按钮「**大模型判断关系**」
2. 「一键拉取全部」导入联系人后会**自动静默执行**一次

![绿泡泡连接器页](shots/20_connector_page.png)

连接器页上可读到的状态：「已在库 13 / 16 位」、「已连接，发现 16 位可拉取好友」、「大模型：本地模拟（未配置 API）」，以及流程提示「浏览好友卡片 → 一键拉取 → 自动生成人脉卡片与关系连线」。

点下「大模型判断关系」，推断完成后弹出结果：

![大模型判断关系结果](shots/21_llm_judge_result.png)

弹窗内容逐行为：

```
模式：本地模拟
与我的关系分：更新 18 人
人物间关系：推断 6 条

关系分已写入连线（颜色/长短随分数变化），可随时手动补充修正。
```

返回关系网络页，图上多出几条线，关系分也重算了一遍：

![推断后的网络](shots/22_after_judge.png)

连接器页底部状态栏会同步显示一行摘要，格式为：

> 大模型（本地模拟）：更新与我的关系分 18 人，推断关系 6 条 · 免费

### 2.2 它究竟推断出什么

推断结果分两部分，**都会直接写入数据库**：

**（一）与「我」的关系属性**

| 字段 | 含义 | 写入位置 |
|---|---|---|
| `closeness` 亲密度 | 你和此人的亲近程度 | `persons.closeness` |
| `sentiment` 情感权重 | 你对这段关系的主观看重程度 | `persons.sentiment_weight` |
| `score` | 该人的综合关系分 | 参与评分计算 |
| `reason` | 判断依据 | 随结果返回 |

**（二）人物之间的关系**

| 字段 | 含义 |
|---|---|
| `a` / `b` | 关系两端的人物 |
| `relation` | 关系类型（缺省「认识」；「合作」会被归一为「合作伙伴」） |
| `score` | 该条关系的分数（0–100，缺省 50） |
| `note` | 这条关系的来源说明，例如「陈学长 由 王教授 引荐」「沙盒好友关系」 |

写库规则：同一对人（不分方向）已存在同类关系时，**更新**它的备注与分数；不存在才新建。两端为空或指向同一人则跳过。

### 2.3 推断的输入：它看到了什么

喂给模型的人物信息包括：**姓名、关系类型、亲密度、情感权重、引荐人、生日**。

另外，联系人沙盒里的好友关系会作为**权威补充信息**一并注入，格式为「已知好友关系：A-B(关系)」。

调用参数固定为 `temperature=0.2`、超时 60 秒，返回内容按首尾花括号截取 JSON 解析。

### 2.4 为什么它不会凭空编造关系（关键设计）

这是本功能可信度的核心。推断结果要穿过**五道闸门**才能落库：

| # | 约束 | 作用 |
|---|---|---|
| 1 | **亲属关系白名单剔除** | 模型返回的任何亲属类关系（16 个亲属关系词）**一律丢弃**，模型无权生成亲属关系 |
| 2 | **候选边限制** | 模型返回的连接只保留落在**已知候选边集合**内的——即模型**不能新增连线**，只能对已有候选边赋予关系类型与分数 |
| 3 | **亲属边由规则推导** | 亲属连接改由 `explicit_family_links` 规则生成（见下） |
| 4 | **人名校验** | 关系两端必须是库中真实存在的人名，且不能自己连自己；关系分同样按库中人名过滤 |
| 5 | **数值裁剪** | 分数强制转整数并裁剪到 0–100，非法值回落 50 |

**亲属关系的推导规则**（`explicit_family_links`）——必须**同时**满足以下全部条件才建立一条亲属边：

1. 长辈一侧的亲属元数据中 `generation`（代际）为整数；
2. `family`（同族标识）非空，且**双方同族**；
3. 代际**严格相邻**：对方的代际 = 长辈代际 + 1；
4. **明确指定对方**：对方必须出现在长辈的 `younger`（晚辈）列表中；
5. 关系词在白名单内：家人 / 母子 / 母女 / 父子 / 父女 / 姑侄 / 叔侄 / 伯侄 / 舅甥 / 姨甥。

满足则生成一条 `score=78` 的亲属边，并在备注里记录推导依据（长辈、晚辈、代差）。

> 换句话说：**亲属关系只在「同族 + 相邻代 + 明确点名」三者齐备时才建立**，不会因为两个人同为「家人」就两两连边，也不会按姓名或年龄去猜。

### 2.5 无 API 密钥时：本地模拟模式

没有配置模型密钥时，软件走**本地模拟（mock）模式**。这不是「假装在算」，而是一套**确定性启发式**：

**与我的关系分**：

\[
\text{score} = \text{base}(\text{关系类型}) + 8 \times \text{closeness} + 4 \times \text{sentiment}
\]

有生日 +3，有引荐人 +2，最终裁剪到 5–99。随后反推回写 `closeness` 与 `sentiment`。

**人物之间的关系**，按三个来源依次合并（无向去重）：

1. **亲属边**：由上述 `explicit_family_links` 规则生成（`score=78`）；
2. **沙盒好友关系**中的非亲属边：`score = clamp(70 × 平均亲密度 + 0.3 × 关系基准, 20, 95)`，备注「沙盒好友关系」；
3. **引荐链**：关系类型「引荐」，`score=70`，备注「X 由 Y 引荐」。

这两部分**不使用任何随机数或当前时间**，所以**相同输入必得相同输出**，可复现、可离线、完全免费。

推断把分数写进库后，分数**怎么来的**写在资料卡里。右键人物 →「打开资料卡」，或点右侧「维护优先级」的任意一行：

### 2.7 五维评分：你没意识到的关系属性，量化在这里

总分由五个维度加权，权重合计 1.0：

\[
\text{score} = 100 \times (0.30\,r + 0.20\,s + 0.20\,p + 0.20\,u + 0.10\,c)
\]

| 符号 | 维度 | 权重 | 计算规则 |
|---|---|---|---|
| \(r\) | **亲密度** | 0.30 | 由关系类型映射：家人 1.00 / 挚友 0.90 / 重要合作伙伴 0.85 / 同事 0.60 / 普通朋友 0.50 / 弱关系 0.30 |
| \(s\) | **情感权重** | 0.20 | 你对这段关系的主观看重程度（可在资料卡滑杆调整） |
| \(p\) | **互惠度** | 0.20 | \(\min(1,\ (\text{送出礼物次数} + \text{收到礼物次数}) / 4)\)，即 **4 次礼物往来即满分** |
| \(u\) | **紧迫度** | 0.20 | 按距下一个生日/重要日期的天数：无日期 0.20；≤7 天 1.00；≤30 天 0.70；≤90 天 0.40；其余 0.20 |
| \(c\) | **网络中心度** | 0.10 | 基础 0.5；**有引荐人 +0.3**；**自己是引荐枢纽 +0.2**（上限 1.0） |

**档位划分**：≥80 核心 / 65–79 重要 / 45–64 普通 / <45 浅层。

**关系保底**：家人、挚友不低于 **65** 分；重要合作伙伴不低于 **60** 分。理由是这些是「天然重要」的关系，即使当前没有临近节日、往来也少，也不该掉到普通档以下。

> **这就是「你没意识到的关系属性」的具体含义**：网络中心度会告诉你某个人其实是你社交圈的枢纽（他引荐了好几个人给你）；紧迫度会告诉你三天后有个你忘了的合作周年；互惠度会告诉你这段关系你一直在收、没有回。这三项都不是你录入的，是算出来的。

## 核心功能三：关系改善与升温

看清了、补全了，接下来才是真正的目的：**让关系变好**。这一节回答三个问题——今天该联系谁、怎么联系、联系完怎么记。

### 3.1 今天该联系谁：右侧任务栏

右侧任务栏是升温动作的调度中心，共五张卡片，可整体用「面板」按钮隐藏，也可拖拽调宽。

![右侧任务栏上部](shots/30_sidebar_top.png)

#### ① 近期提醒

列出有生日或重要日期的人，按「距下次日期的天数」**升序**排列，最多 8 位。

- **颜色预警**：≤7 天显示为红色，≤30 天显示为黄色。
- **30 天内的行**直接带行动按钮：「**祝福**」「**送礼**」，点了就跳到对应页面并自动选好人。
- 没有重要日期时显示「（暂无重要日期）」。

此外，**启动时会自动弹出 7 天内的提醒窗**，标题「近期提醒 · 该维护谁了」，说明「7 天内的生日 / 纪念日，点行动按钮直接处理：」，按钮为「去送礼」「写祝福」「知道了」。

#### ② 网络概览

四个统计数字：**人物总数**、**核心人物**数、**平均分值**、**30 天内提醒**数。切场景时这四个数字跟着变。

#### ③ 快速补关系

不用进画布就能补一条关系：两个人物下拉 + 关系类型下拉（默认「认识」）+ 关系分（默认 50）+「**建立**」按钮。

#### ④ 维护优先级

![维护优先级](shots/31_sidebar_rank.png)

- 按**综合关系分降序**，取前 8 位。
- 每行显示：序号徽章、姓名、分数、档位 chip、分数条。
- **点击整行直接打开资料卡**。
- 超出部分提示「还有 N 位，去「人脉卡片」查看」。

> **怎么用这张榜**：高分不代表「必须联系」，而是「这段关系值得你优先投入精力」。真正的行动信号是「高分 + 紧迫度高」或「高分 + 互惠度低」——前者是有节点要到了，后者是你一直在欠人情。两项都在资料卡的五维拆解里看。

#### ⑤ AI 助手

对话式入口，欢迎语是「我是关系网络助手，直接说人话就行：找谁、补关系、写祝福。」可选模型，可点「API」配置，可点「纪要」导入文本。

无 API 密钥时它会列出本地能做的事：查资料/生日/地址、调关系分、记备注、建立连接、查两人关系、找谁帮忙。

### 3.2 怎么联系（一）：祝福语

「祝福语」页是最轻量的升温动作。

![祝福语页](shots/34_greet_result.png)

#### 单人定制

1. 选「**人物**」（例：王教授）
2. 选「**节日**」（例：教师节），也可以点下方节日模板 chip：春节 / 生日 / 中秋 / 端午 / 女神节 / 教师节 / 合作周年 / 新年
3. 选「**模型**」（可选，默认跟随全局配置）
4. 点「**生成专属祝福**」

结果出现在左侧「祝福语预览」区，**可以直接编辑**，旁边有「**复制**」按钮。

生成的内容会真实用到这个人的资料。上图中的输出：

> 【王教授】教师节快乐🎉！重要合作伙伴感念一路指引，记得您爱茶、书法、历史书，略备薄礼表心意。愿桃李芬芳，康乐顺遂。（教师节茶叶）每一次关键决策，都感谢您的信任。

注意其中两处细节：「爱茶、书法、历史书」来自资料卡的**喜好**字段；「（教师节茶叶）」来自**互动记录里上次送过什么**。这就是记忆在发挥作用。

页脚会标明本次计费情况，例如「已生成（本地模板）· 免费」；走真实 API 时显示「扣 2 积分，余额 N」。

#### 节日群发

右栏「节日群发」用于批量：

1. 勾选对象（或点「全选」/「清空」），计数显示「已选 N 人」
2. 点「**一键群发祝福**」
3. 「**撰写进度**」区实时显示百分比与「已完成 N / 共 M · 还剩 K 位」
4. 「**撰写结果**」区逐行显示状态：等待中 → 撰写中… → 已完成，每行有「查看」按钮
5. 完成后可点「**复制全部**」

群发**按关系分从高到低排队**——重要的人先写。

#### 分档模型：不同交情不同待遇

「**分段祝福模型（按关系分 · 社交成本）**」区可以给四个档位分别指定模型：

| 档位 | 分数区间 | 示例配置 |
|---|---|---|
| 核心 | ≥80 | hunyuan-lite（低成本） |
| 重要 | 65–79 | （跟随全局） |
| 普通 | 45–64 | deepseek-reasoner（中成本） |
| 浅层 | <45 | （跟随全局） |

每个下拉旁标注该模型的成本档（低成本 / 中成本 / 高成本）。点「全部统一」可一键重置为跟随全局。配置保存在 `llm_config.json` 的 `greet_tier_models` 字段，**设置本身不花钱**。

### 3.3 怎么联系（二）：智能送礼

![智能送礼页](shots/35_gift_page.png)

#### 推荐逻辑

选「**为谁选礼**」后，表格「**推荐礼物（按喜好匹配 + 性价比排序）**」列出候选，字段为：礼物 / 类别 / 到手价 / 匹配 / 性价比。

推荐规则（本地计算，完全免费）：

1. **禁忌直接排除**——命中这个人禁忌字段的礼物根本不进候选；
2. 匹配分 = 命中喜好数 × 2 + 关系类型适配；该人没有录喜好时给基础分 1；
3. 到手价取所有商家中的**最低价**；
4. 性价比 = 匹配分 ÷（最低价 / 100）；
5. 按匹配与性价比排序。

> ⚠️ **推荐不读预算、也不读综合关系分**。它只看喜好、禁忌与关系类型适配，再除以价格。界面上也没有预算输入框。

#### 多商家比价

选中一行礼物后，下方「**多商家比价**」展开各商家报价，最低价标注「←最低」，并显示「到手价 ¥XX（已选最低渠道）」与该人的收货地址。

> 比价区明确标注「**演示价 · 商家与价格均为模拟数据**」。这是演示数据，不是实时电商报价。

#### 下单与付款

右栏「下单」区：选送达日期、选付款通道，然后付款。

| 通道 | 按钮 | 行为 |
|---|---|---|
| **模拟支付（演示）** | 「模拟一键付款」 | 仅本地把订单标记为「模拟已付款」，**演示不扣款**，不产生真实交易 |
| **Vibe Pay** | 「Vibe Pay 付款」 | 在浏览器打开支付宝收银台，由你本人付款，到账后自动确认 |

「最近订单」表显示 ID / 人物 / 礼物 / 金额 / 日期 / 状态，Vibe 通道的订单状态会加「Vibe·」前缀。

### 3.4 联系完一定要做的事：记一笔

![记录联系](shots/36_record_contact.png)

入口：资料卡底部「**记录联系**」，或在关系网络右键人物 →「记录联系」。

窗口标题「记录联系 · 某某」，说明「填写实际联系的日期、类型和备注，点击保存后记入互动历史。」

| 字段 | 说明 |
|---|---|
| **联系日期** | 默认今天，格式必须是 `YYYY-MM-DD`，格式错会提示「请填写有效的日期，格式为 YYYY-MM-DD。」 |
| **联系类型** | 下拉：电话 / 见面 / 聊天 / 邮件 / 其他 |
| **备注** | 多行文本 |

点「保存联系」后：写入互动记录表 → 资料卡的互动区即时刷新 → 人脉卡片刷新 → 状态栏提示「已记录与「某某」的电话」。

> ### ⚠️ 关于互惠度的重要提示
>
> **互惠度维度只统计类型为「送出礼物」或「收到礼物」的互动记录。**
>
> 这意味着两件事：
>
> 1. 用下拉里的「电话 / 见面 / 聊天 / 邮件 / 其他」记一笔，会进入**互动记录列表**（也会被祝福语生成当作上下文读取），但**不会提升互惠度分数**。
> 2. **送礼页下单付款本身不会自动写入「送出礼物」互动记录**。送完礼如果想让互惠度上去，需要另外手动记一笔，并把类型写成「送出礼物」。
>
> 这是当前版本的真实行为，请据此安排使用习惯。如果你希望「下单即自动记一笔」，这需要改动软件。

### 3.5 人脉卡片页：批量维护

![人脉卡片页](shots/33_cards_page.png)

当你要一次性补很多人的资料时，用「人脉卡片」页比逐个开资料卡快。

每张卡片包含：层级色带、头像、姓名、档位胶囊、分数胶囊（「XX 分」）、来源标记（如「绿泡泡」），以及一组**可直接编辑**的字段：

> 关系（下拉）/ 亲密 / 情感 / 引荐人 / 电话 / 生日 / 重要日期 / 收货地址 / 喜好 / 禁忌 / 备注

下方是「**场景**」勾选区（决定这个人出现在哪些场景里），按钮为「保存」「删除」「送礼」「祝福」。

**字段录入格式**：

| 字段 | 格式 | 示例 |
|---|---|---|
| 生日 | `YYYY-MM-DD` | `1972-09-10` |
| 重要日期 | `标签:日期`，多条用逗号分隔 | `合作周年:2026-11-20, 入职纪念:2025-03-01` |
| 喜好 / 禁忌 | 用「、」分隔 | `茶、书法、历史书` |

> **生日和重要日期直接决定紧迫度维度**，也直接决定右侧「近期提醒」会不会提醒你。这两个字段是整个升温闭环的燃料，值得花时间补全。

### 3.6 一次完整的升温闭环

把上面的功能串起来，典型的一轮是这样：

```
启动 → 弹出「近期提醒」：王教授 合作周年 3 天后
  ↓
点「写祝福」→ 跳到祝福语页，人物与节日已选好
  ↓
点「生成专属祝福」→ 输出里自动带上他的喜好（茶、书法）和上次送的礼（教师节茶叶）
  ↓
复制发出去
  ↓
回到资料卡 → 点「记录联系」→ 类型「送出礼物」、备注写清送了什么
  ↓
互惠度上升 → 综合分重算 → 维护优先级重排
```

这个闭环的每一步都有数据留痕，下一次生成祝福时，这些留痕又成为新的上下文。

## 六、账号与数据

### 6.1 多账号

- **新建**：账号入口层点「＋ 新建账号」。
- **切换**：主界面右上「退出登录」回到入口层再选，提示为「将退出当前账号并回到账号入口，本机数据保留。继续？」
- **隔离级别**：**物理隔离，一个账号一个数据库文件**。默认账号用 `data/agent.db`，其他账号用 `data/accounts/<账号标识>/agent.db`。账号清单存 `data/accounts.json`。

> 账号与场景是两层概念：**账号隔离的是数据**（互不可见），**场景过滤的是视图**（同一账号内切换人群）。日常看不同人群请用场景卡，不要靠切账号。

### 6.2 数据文件清单

默认数据根目录为程序目录下的 `data/`，可用环境变量 `JINBU_DATA_DIR` 指定。打包为 exe 运行时，数据目录取 **exe 所在目录**，配置跟着 exe 走。

| 文件 | 内容 |
|---|---|
| `data/agent.db` | 当前账号的全部人物、关系、互动、订单、积分流水 |
| `data/accounts.json` | 账号清单 |
| `data/accounts/<slug>/agent.db` | 非默认账号的独立库 |
| `llm_config.json` | 模型配置（服务商、地址、密钥、模型名、分档模型） |
| `cloud_client.json` | 云端服务器地址 |
| `data/cloud_session.json` | 云端登录态（有效期 30 天） |
| `data/avatars/avatar_<id>.png` | 人物头像（`avatar_0.png` 是「我」） |

## 八、模型配置与云端模式

### 8.1 两种运行模式

| 模式 | 触发条件 | 行为 |
|---|---|---|
| **本地模拟（mock）** | 未配置密钥（默认） | 确定性启发式算法，离线可用、结果可复现、完全免费 |
| **API 实连** | 已配置完整密钥 | 调用 OpenAI 兼容接口，按积分计费；**失败自动降级 mock 并提示** |

当前模式在界面上有明确标识，例如页面右上的「● 本地模拟运行」，或「大模型：本地模拟（未配置 API）」。

### 8.2 配置模型

入口：关系网络页右侧 AI 助手区的「**API**」按钮。

![模型配置](shots/41_llm_config.png)

流程是「**选预设 → 填 Key → 测试连接 → 保存**」。

内置服务商预设：

| 预设 | 可选模型 |
|---|---|
| **腾讯混元（Lite 永久免费）** | hunyuan-lite / hunyuan-turbos-latest / hunyuan-t1 / hunyuan-standard |
| **火山方舟（豆包）** | doubao 系列 |
| **DeepSeek** | deepseek-chat / deepseek-reasoner |
| **自定义（OpenAI 兼容）** | 自填 |

> **免费额度提示**：腾讯混元 Hunyuan-Lite 永久免费（每日 1 万 token，学生认证 5 万/天），首次开通另送 100 万 token 资源包（1 年有效）。申请路径：腾讯云控制台 → 混元大模型 → API 密钥管理。

**成本标识**：每个模型旁标注「低成本 / 中成本 / 高成本」，仅作选型提示，不影响调用本身。配合祝福语页的分档模型设置，可以做到「核心的人用好模型，浅层的人用便宜模型」。

「**测试连接**」会发一条最小请求验证配置；字段没填全会提示「base_url / api_key / model 未填完整」。

### 8.3 云端模式

入口：「更多」→「**云端账号与 AI…**」，窗内有「测试连接」「注册并登录」「启用/停用云端」「退出账号」。

**云端解决的核心问题是密钥安全**：

| | 本地模式 | 云端模式 |
|---|---|---|
| 模型密钥位置 | 存在本机 `llm_config.json` | **只在服务端**，通过环境变量注入 |
| 客户端持有 | 完整密钥 | **只有服务器地址与登录 Token，拿不到密钥** |
| 计费与记账 | 本地积分账本 | 服务端账本，桌面端只拿结果与扣费记录 |
| 数据存储 | 本机 SQLite，不上传 | 账户与积分在服务端，关系数据仍在本机 |

**安全机制**：密码使用 PBKDF2-HMAC-SHA256 加盐哈希（21 万次迭代），Token 只存哈希值，会话有效期 30 天。服务端 AI 调用采用预扣 + 幂等退款，异常重启也会退款。

服务端默认监听 `127.0.0.1:8765`；**对公网提供服务必须用 HTTPS 反向代理**。

## 九、常见问题与边界说明

**Q：线的颜色到底代表什么？**
关系**类型**（家人 / 挚友 / 合作伙伴 / 同事 / 引荐 / 认识，亲属统一暖棕）。分数档位由**卡片颜色**表达。两者不要混说。

**Q：为什么默认看不到大部分关系线？**
为了可读性，默认只显示亲属线。悬停某人展开他的关系，或勾选「显示全部连线」一次全显。

**Q：没有 API 密钥，「大模型判断关系」还能用吗？**
能，走本地模拟模式，完全免费，结果可复现。它仍会推导亲属关系、沙盒好友关系与引荐链，只是不具备自然语言理解能力。

**Q：Agent 会不会编造关系？**
不会向数据库写入凭空关系。亲属关系只在「同族 + 相邻代 + 明确点名 + 关系词白名单」全部满足时才建立；模型返回的连接只能落在已知候选边上，不能新增连线。中心线（我→每个人）是展示层效果，不写库。

**Q：送礼下单后，关系分会自动上升吗？**
**不会自动。** 互惠度维度只认类型为「送出礼物 / 收到礼物」的互动记录，而下单付款链路不写互动记录。送完礼请手动「记录联系」，类型写「送出礼物」。

**Q：礼物推荐会考虑我的预算吗？**
不会。推荐只看喜好匹配、禁忌排除、关系类型适配，再除以最低价算性价比。比价数据是**模拟演示数据**。

**Q：我拖好的人物位置，会被自动布局弄乱吗？**
不会。手动拖拽过的卡片在防重叠计算中永不被推动。只有你主动执行「自动布局」（有二次确认）才会清空所有手动位置。

**Q：换了账号，我的关系数据会混在一起吗？**
不会。一个账号一个独立的数据库文件，互不可见。

**Q：首次点其他页签有点慢？**
正常。v0.69 为了加快启动，只优先构建关系首页，其余四页首次打开时才构建。

**Q：更换了人物头像/界面图片，exe 里没变？**
exe 内的界面图片来自打包快照，换图必须重新打包；当前版本未实现「外部目录优先」的热更新。

## 附录 B：评分公式与颜色口径

### 综合关系分

\[
\text{score} = \mathrm{round}\Big(100 \times (0.30\,r + 0.20\,s + 0.20\,p + 0.20\,u + 0.10\,c)\Big)
\]

其中各维度取值范围均为 \([0,1]\)：

\[
r = \text{RELATION\_WEIGHT}(\text{关系类型}),\quad
p = \min\!\left(1,\ \frac{n_{\text{送出}} + n_{\text{收到}}}{4}\right)
\]

\[
u = \begin{cases}
1.00, & d \le 7\\
0.70, & 7 < d \le 30\\
0.40, & 30 < d \le 90\\
0.20, & d > 90 \text{ 或无日期}
\end{cases}
\qquad
c = \min\!\big(1,\ 0.5 + 0.3\,[\text{有引荐人}] + 0.2\,[\text{是枢纽}]\big)
\]

\(d\) 为距下一个生日或重要日期的天数，\(s\) 为情感权重（用户可调）。

**关系类型权重**：家人 1.00 / 挚友 0.90 / 重要合作伙伴 0.85 / 同事 0.60 / 普通朋友 0.50 / 弱关系 0.30。

**保底**：家人、挚友 ≥65；重要合作伙伴 ≥60。
